# Blueprint case access and dispatch approval

These pure checks back the n8n case-name search, saved retainer reader, and post-signature dispatch gate. They contain no provider credentials or client files.

- `case-name-query.cjs`: case/party/address terms for fresh reads of both Airtable tables; no record ID question is needed.
- `case-asset-boundary.cjs`: a requested file must belong to the verified case root, or its verified retainer review child. Another case or similarly named folder is rejected. Version, parent and case bindings are checked again after reading.
- `dispatch-approval.cjs`: owner signature and notice approval do not authorize process-server delivery. Approval binds the current signed request, PDF digest, case/folder, intended recipient, mode and reviewer. The existing delivery claim still prevents duplicate sends.
- `dispatch-command-guards.cjs`: an explicit approval command must match the actual completed signed package, reviewer, recipient and test/live mode before delivery can run.
- `dispatch-review-receipts.cjs`: read-only review reconciles the saved approval and exact delivery receipt. An owned test email is reported as test delivery, and a missing or mismatched receipt stays unresolved. Signing, sending and case tracking remain distinct facts.
- `service-proof-policy.cjs`: proof must match the case name and full premises, including unit/ADU. Multiple matching orders remain ambiguous rather than selecting the newest. Dates must be valid calendar dates, and approval binds the actual proof, proposed fields and unchanged case snapshot.

Service deadline automation is limited to supported three-day pay-or-cure notices. Other notice types require office review of the deadline. This follows the [California Courts notice-type guidance](https://selfhelp.courts.ca.gov/eviction-landlord/notice-types) and [counting instructions](https://www.selfhelp.courts.ca.gov/eviction-landlord/fill-out). The current proof worker's human approval gate is retained while its Grok review journey is being completed.

Active workflows are identified in the business CTO runbook. Inspect their actual current versions before a change; preserve current credentials, settings, static data and unrelated nodes. Back up, test, publish, read back and retain rollback evidence. These source checks do not establish that an automatic card, signature completion, or delivery has passed acceptance.

Readable PDF source text uses the authenticated `/inspect-source-pdf` endpoint, hashes the uploaded bytes, includes actual filled form values and never fetches caller URLs or infers missing facts. Blank scans report an OCR need; a read failure is not absence. Existing source-research and signing approval guards remain independent.

The controlled proof worker now has a Grok review path. It saves and verifies the original PDF before review, keeps the full case/address/unit snapshot, and protects the execution-specific approval callback with n8n Header Auth. The backend returns a filtered review, never its private callback. Exact current proposal/PDF/date/mode/reviewer approval and a fresh case read are required before the existing guarded filing, attachment append and date/status writes. Repeated filing claims are not replayed.

The existing native Airtable client-update email says that service was by posting and mailing. The worker therefore holds a different service method, unsupported notice deadline or served-only proposal for office review before changing status. It does not change that approved email wording or infer delivery from an Airtable status. The normal service-proof entry now uses this worker, with the old nodes and waiting executions preserved. An incoming duplicate reused its verified filing receipt. These results do not certify inaccessible company libraries or the entire notice/retainer system.


The current reply's PDF takes precedence over older thread packets. Multiple distinct PDFs on the current reply remain held; identical-byte copies count once. Run `node integrations/n8n/case-access/test-proof-attachment-policy.cjs` for this captured selection behavior. Existing filing receipts are reread with current PDF bytes, folder binding, attachment and dates before a duplicate is reported as already filed; a partial or changed result is held for reconciliation.

`proof-notification-policy.cjs` keeps ordinary correspondence without attachments or proof intent out of proof processing. Thread recovery remains available for genuine proof requests. Both text extraction and OCR must classify the actual PDF as a notice proof of service before proposing notice dates; leases, ledgers, invoices and court-summons proofs do not qualify. Non-proof mail is silent; genuine uncertain proof remains a review item. This gate does not alter the independent case-asset filing route. Actual ordinary-email and positive-proof checks passed in the live worker. Run `node integrations/n8n/case-access/test-proof-notification-policy.cjs`.

A PDF explicitly identified by the message as proof must not disappear because its subject lacks the required case/address format or its size exceeds the supported limit. Those gate failures become a Pending item for the CTO to reconcile; ordinary attachments and messages without a PDF remain quiet. No date/status write is authorized by that Pending notification.

Signed-retainer return handling uses `retainer-pdf-attachment.cjs` and `retainer-case-identity.cjs`. The bounded PDF limit is 20 MiB; current generated retainers exceed the earlier 4 MiB limit. It preserves the received bytes and content digest, requires a single complete PDF attachment, and keeps document classification and source authentication separate. This bound is below the [file-input limit](https://developers.openai.com/api/docs/guides/file-inputs) and [OneDrive upload-session request limit](https://learn.microsoft.com/graph/api/driveitem-createuploadsession).

Full case name, premises and reciprocal notice/eviction links determine the existing folder. An added ADU/unit can refine a legacy address that omits a unit only when both tables identify exactly one reciprocal case pair at the same base address. It never ignores an explicit conflicting unit, different street type, ZIP conflict or duplicate case. The document address is retained as evidence; this allocation step does not change the Airtable address or create/rename a folder. Clearly simulated returns are restricted to exactly bound owned test records; they are not evidence of a genuine provider signature. Run `node integrations/n8n/case-access/test-retainer-return-policy.cjs`.

The Orders asset handoff runs its existing protected child independently. Its immediate output means dispatched, not filed. Actual child receipts still determine whether storage succeeded. An unresolved identity review must not block the mailbox producer; historical held jobs remain untouched. Info paths that consume verified child receipts retain their existing wait behavior.

Company office evidence uses a separate read-only tool scoped to case source categories under the existing company Data Folder. Search misses and partial listings are not proof of absence. PDF source reads preserve original hashes and real page numbers; explicit windows of at most five pages can return bounded source excerpts for OCR. The original case files and Orders case-folder bindings are never moved, renamed or rewritten by this reader.
